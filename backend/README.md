# yaneMedia backend

API на NestJS для каталога, поиска, аккаунтов, избранного, истории и отзывов. Media Engine находит источники просмотра, PostgreSQL хранит данные приложения.

Для запуска всего приложения через Docker используйте [общий README](../README.md).

## Локальный запуск

Нужны Node.js 24, Bun и работающий PostgreSQL. Откройте терминал в корне скачанного или склонированного проекта и выполните `cd backend`. Команды этого README запускаются из папки `backend`, обозначенной ниже как `yaneMedia/backend`.

```sh
# Папка: yaneMedia/backend
bun install --frozen-lockfile
cp .env.example .env
```

Заполните `.env`:

| Настройка                     | Для чего нужна                                                                              |
| ----------------------------- | ------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                | Подключение к PostgreSQL.                                                                   |
| `FRONTEND_ORIGIN`             | Адрес интерфейса, по умолчанию `http://localhost:5173`.                                     |
| `RESEND_API_KEY`, `MAIL_FROM` | Необязательная отправка писем. Для регистрации и восстановления доступа нужны оба значения. |
| `TMDB_API_KEY`                | Данные фильмов и сериалов, наполнение каталога.                                             |
| `KODIK_API_KEY`               | Подключение Kodik, если нужен этот источник.                                                |

Остальные настройки и значения по умолчанию — в [`.env.example`](.env.example).

Без настроенной почты приложение запускается и работает для гостей. Вход в уже подтверждённый аккаунт остаётся доступным; новые аккаунты требуют подтверждения email. Регистрация без почты возвращает понятную ошибку и не создаёт пользователя. Запрос восстановления сохраняет одинаковый ответ для любых адресов, но письмо не отправляется.

```sh
# Папка: yaneMedia/backend
bun run db:migrate
bun run start:dev
```

API: **[localhost:3000/api/v1](http://localhost:3000/api/v1)**. Проверка работы: [health](http://localhost:3000/api/v1/health).

## Каталог

После первого запуска заполните подборки и загрузите постеры:

```sh
# Папка: yaneMedia/backend
bun run build
bun run catalog:sync
```

Команда использует внешние источники данных и публикует каталог после успешного наполнения. Для предварительного просмотра изменений выполните `bun run catalog:sync --dry-run`.

## Основные команды

Все команды таблицы запускайте из `yaneMedia/backend`.

| Команда                                                                       | Действие                                   |
| ----------------------------------------------------------------------------- | ------------------------------------------ |
| `bun run start:dev`                                                           | Запуск с перезагрузкой при изменении кода. |
| `bun run build`                                                               | Сборка backend.                            |
| `bun run db:generate`                                                         | Создание миграции после изменения схемы.   |
| `bun run db:migrate`                                                          | Применение миграций.                       |

## Torrent

При локальном запуске из `.env.example` серверный torrent выключен. Для домашнего просмотра используйте режим Home из корня проекта: он подключает TorrServer и необходимые секреты.

Поиск раздач обращается только к JSON API: JacRed (`JACRED_BASE_URL`) и независимому [Knaben v2](https://knaben.org/api/v2/) (`KNABEN_BASE_URL`) параллельно. `JACRED_FALLBACK_URLS` задаёт до двух резервных JacRed origins через запятую. Пример настроек — в `.env.example`; для отключения поиска очистите все три значения, ручной ввод magnet/`.torrent` останется доступен.

JacRed принимает все 25 известных трекеров его [каталога](https://github.com/jacred-fdb/jacred/blob/main/docs/trackers/overview.mdx), а также совместимые записи Pirate Bay/YTS/1337x/Nyaa. Наличие конкретного трекера зависит от наполнения выбранного API. Объединённая запись относится к фактическому хосту её topic URL; остальные названия не создают фиктивных копий. Knaben добавляет собственные источники, включая Nyaa, YTS, 1337x и The Pirate Bay. Между каталогами удаляются дубликаты одного hash на одном трекере.

Каждый API-запрос ограничен 4 секундами и 2 MiB, редиректы и HTML отклоняются. Отказавший API пропускается на 60 секунд; успешные ответы кэшируются на минуту (до 100 записей). Во время отказа можно вернуть результаты этого же запроса не старше 10 минут с `stale/degraded`. Доступные результаты другого API сохраняются. При полном отказе без подходящего кэша возвращается `TORRENT_DISCOVERY_UNAVAILABLE`, а не фиктивный пустой успех. В браузер передаются только metadata и owner-scoped `candidateRef`; magnet и внутренние адреса остаются на сервере.

Для диагностики без скачивания торрентов: `docker compose exec -T backend npm run probe:torrent-discovery -- --query Oppenheimer --rounds 2` из корня проекта. Выводит время, трекеры, каталоги и признак деградации, без magnet/credentials. Первый запрос проверяет сеть; второй может использовать кэш.

Другие API-аналоги — [Jackett](https://github.com/Jackett/Jackett/wiki/Jackett-API) и [Prowlarr](https://prowlarr.com/docs/api/). Им требуются свой настроенный экземпляр и API key; публичными резервами без настройки они не являются и сейчас не подключены. HTML трекеров приложение не парсит.

Первый запуск — в [короткой инструкции Home для Windows, Linux и macOS](../torrserver/SETUP.md), проверки — в [руководстве по torrent-тестам](test/torrent/README.md).
