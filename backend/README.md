# yaneMedia backend

API на NestJS для каталога, поиска, аккаунтов, избранного, истории и отзывов. Media Engine находит источники просмотра, PostgreSQL хранит данные приложения.

Для запуска всего приложения через Docker используйте [общий README](../README.md).

## Локальный запуск

Нужны Node.js 24, Bun и работающий PostgreSQL. Откройте терминал в корне скачанного или склонированного проекта и выполните `cd backend`. Команды этого README запускаются из папки `backend`, обозначенной ниже как `yaneMedia/backend`.

```sh
# Папка: yaneMedia/backend
bun install --frozen-lockfile
cp .env.example .env
```

Заполните `.env`:

| Настройка                                              | Для чего нужна                                                                           |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `DATABASE_URL`                                         | Подключение к PostgreSQL.                                                                |
| `FRONTEND_ORIGIN`                                      | Точный адрес сайта без завершающего `/`. Используется для CORS, CSRF и ссылок в письмах. |
| `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` | Настройки отправки писем. Для регистрации и восстановления нужны все четыре значения.    |
| `SMTP_PORT`                                            | По умолчанию `587` с обязательным STARTTLS. На `465` TLS включается сразу.               |
| `TMDB_API_KEY`                                         | Данные фильмов и сериалов, наполнение каталога.                                          |
| `KODIK_API_KEY`                                        | Подключение Kodik, если нужен этот источник.                                             |

Остальные настройки и значения по умолчанию — в [`.env.example`](.env.example).

Без настроенной почты приложение запускается и работает для гостей. Вход в уже подтверждённый аккаунт остаётся доступным; новые аккаунты требуют подтверждения email. Регистрация без почты возвращает понятную ошибку и не создаёт пользователя. Запрос восстановления сохраняет одинаковый ответ для любых адресов, но письмо не отправляется.

```sh
# Папка: yaneMedia/backend
bun run db:migrate
bun run start:dev
```

API: **[localhost:3000/api/v1](http://localhost:3000/api/v1)**. Проверка работы: [health](http://localhost:3000/api/v1/health).

## Почта на публичном сервере

В Brevo добавьте и подтвердите отправителя, активируйте отправку транзакционных писем и создайте SMTP-ключ. SMTP-логин указан на странице SMTP в Brevo. Заполните `backend/.env` на сервере:

```dotenv
FRONTEND_ORIGIN=https://89.112.10.57
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_USER=your-smtp-login
SMTP_PASSWORD=your-smtp-key
MAIL_FROM="yaneMedia <your-verified-sender@example.com>"
```

Подставьте реальные значения логина, ключа и адреса отправителя. При переходе со старой конфигурации удалите `RESEND_API_KEY` и замените старый `MAIL_FROM`. Если сервер использует дополнительный Compose-файл, проверьте, что он не задаёт другой `FRONTEND_ORIGIN`. Пересоберите backend с теми же Compose-файлами, с которыми запущен сервер. [Настройка Brevo SMTP](https://help.brevo.com/hc/en-us/articles/7924908994450-Send-transactional-emails-using-Brevo-SMTP) · [Активация и диагностика](https://help.brevo.com/hc/en-us/articles/115000188150-Troubleshooting-Issues-with-Brevo-SMTP)

## Каталог

После первого запуска заполните подборки и загрузите постеры:

```sh
# Папка: yaneMedia/backend
bun run build
bun run catalog:sync
```

Команда использует внешние источники данных и публикует каталог после успешного наполнения. Для предварительного просмотра изменений выполните `bun run catalog:sync --dry-run`.

При изменении [манифеста подборок](src/media/catalog/editorial-catalog.manifest.json) увеличьте его `version`. Постеры и фоны загружаются с TMDB для фильмов и сериалов и с Shikimori для аниме. Изображения хранятся в WebP. Верхние размеры составляют 640 × 960 для постеров и 3840 × 2160 для фонов. Маленькие изображения сохраняют исходный размер.

Для смены профиля изображений и полной замены сохранённых файлов используйте `catalog:rebuild` внутри backend-контейнера. Команда удаляет существующие ревизии и файлы каталога перед восстановлением. При ошибке загрузки подборки останутся пустыми до успешной пересборки.

## Torrent

При локальном запуске из `.env.example` серверный torrent выключен. Для домашнего просмотра используйте режим Home из корня проекта: он подключает TorrServer и необходимые секреты.

Home и Public используют общие модули каталога, аккаунтов и библиотеки, но разные точки входа. `bun run build` / `bun run start:prod` сохраняют Home. `bun run build:public` компилирует `src/main.public.ts` и нужные ему модули в `dist-public`; локальный запуск — `bun run start:public`. В Public включён только metadata discovery: нет серверных torrent routes, reconciler, HLS/subtitle workers, клиента TorrServer и FFmpeg. Попытка передать Public настройки engine или включить `TORRENT_STREAMING_ENABLED` завершает запуск ошибкой.

Docker targets `home` и `public` выбираются через Compose и имеют разные теги образов. Public runtime содержит только скомпилированный граф, общие миграции и служебные команды каталога; исходники Home и FFmpeg в него не копируются. `db:migrate`, `catalog:sync`, `catalog:rebuild`, `catalog:assets:cleanup` работают в обоих образах. Генерация новых миграций выполняется из исходников, а не внутри Public runtime. Общая схема БД сохраняет домашние сессии и их очистку при logout/reset password; миграций для переключения режима нет.

В обоих режимах `/api/v1/health/ready` описывает готовность API независимо от torrent. `/api/v1/health/ready/torrent` возвращает `ready` в исправном Home и `disabled` в Public. Метрики `/api/v1/health/torrent-metrics` и server video routes доступны только в Home. Поиск `/api/v1/torrent-discovery` остаётся отдельным metadata API по контракту LC-005.

Целевые проверки границы: `bun run test --runInBand --runTestsByPath test/deployment/public-boundary.spec.ts test/deployment/compose-boundary.spec.ts`. Docker-прогон переключения описан в [Home/Public](../docs/home-torrent.md).

Поиск раздач обращается только к JSON API по цепочке: JacRed (`JACRED_BASE_URL`) → до двух резервных JacRed origins (`JACRED_FALLBACK_URLS`, через запятую) → [Knaben v2](https://knaben.org/api/v2/) (`KNABEN_BASE_URL`). Knaben вызывается только после отказа всех настроенных адресов JacRed, либо если JacRed отключён. Успех зеркала или корректный пустой ответ останавливают цепочку. Результаты разных каталогов не смешиваются. Пример настроек — в `.env.example`; для отключения поиска очистите все три значения, ручной ввод magnet/`.torrent` останется доступен.

JacRed принимает все 25 известных трекеров его [каталога](https://github.com/jacred-fdb/jacred/blob/main/docs/trackers/overview.mdx), а также совместимые записи Pirate Bay/YTS/1337x/Nyaa. Наличие конкретного трекера зависит от наполнения выбранного API. Объединённая запись относится к фактическому хосту её topic URL; остальные названия не создают фиктивных копий. Knaben добавляет собственные источники, включая Nyaa, YTS, 1337x и The Pirate Bay. Между каталогами удаляются дубликаты одного hash на одном трекере.

Каждый API-запрос ограничен 4 секундами и 2 MiB, редиректы и HTML отклоняются. Отказавший API пропускается на 60 секунд; успешные ответы кэшируются на минуту (до 100 записей). Свежий резервный каталог проверяется раньше устаревшего кеша. При полном отказе можно вернуть результаты того же запроса не старше 10 минут с `stale/degraded`; без такого кеша возвращается `TORRENT_DISCOVERY_UNAVAILABLE`, а не фиктивный пустой успех. В браузер передаются только metadata и owner-scoped `candidateRef`; magnet и внутренние адреса остаются на сервере.

Для оригинального и локализованного названия собирается полная проверенная выборка в пределах 2 MiB/2000 записей на ответ; общий сетевой deadline остаётся 25 секунд. Квот трекеров и отсечения до 50 больше нет. После проверки публичных magnet, удаления дублей одного hash на одном трекере, исключения записей с явно указанными нулевыми сидами и отсечения размеров свыше 200 GiB весь набор метаданных передаётся браузеру. Неизвестное число сидов (`null`) не считается нулём. До 10 000 owner-scoped candidate refs хранятся не дольше 10 минут; скрытые в интерфейсе позиции также можно выбрать после смены фильтра.

Фильтры и сортировка «Лучшие»/«Сначала новые»/«Больше раздающих» применяются ко всей полученной выборке, затем в список попадают первые 100. Остальные записи не удаляются: при изменении условий состав сотни пересчитывается локально, без нового поиска. Браузер также скрывает нулевые сиды из кешированных ответов и счётчиков фильтров. Строка состояния показывает число отображаемых и подходящих результатов, при фильтрации — также исходное общее число. Для списков длиннее 12 включена виртуализация с измерением высоты карточек, небольшим запасом строк и сохранением Tab-навигации. У списка нет собственной прокрутки: виртуализация использует общий scroll-контейнер меню, учитывая фильтры над списком и закреплённые вкладки. Полоса прокрутки скрыта; колесо, жесты и клавиатура работают. Смена сортировки/фильтров возвращает меню к началу; показ после первых 100 не расширяется прокруткой.

Рейтинг «Лучшие» различает SD/720p/1080p/2160p, источники WEB-DL/BluRay/BDRip/Remux, размер фильма и доступность по сведениям каталога. JacRed передаёт проверенные quality/voices/seasons/relased/types; название дополняет эти поля. Диапазоны сезонов/серий учитываются, год позднего сезона не штрафуется как другой фильм. Рейтинг не удаляет низкое качество из полного набора. Сиды — сведения каталога, не проверка живых пиров; заявленные разрешение и озвучки окончательно проверяются при подготовке видео.

Для диагностики без скачивания торрентов: `docker compose exec -T backend npm run probe:torrent-discovery -- --query Oppenheimer --rounds 2` из корня проекта. Выводит время, трекеры, каталоги и признак деградации, без magnet/credentials. Первый запрос проверяет сеть; второй может использовать кэш.

Другие API-аналоги — [Jackett](https://github.com/Jackett/Jackett/wiki/Jackett-API) и [Prowlarr](https://prowlarr.com/docs/api/). Им требуются свой настроенный экземпляр и API key; публичными резервами без настройки они не являются и сейчас не подключены. HTML трекеров приложение не парсит.

Первый запуск — в [короткой инструкции Home для Windows, Linux и macOS](../torrserver/SETUP.md), проверки — в [руководстве по torrent-тестам](test/torrent/README.md).
